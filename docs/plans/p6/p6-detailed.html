P6 — Packaging & Distribution (DELIBERATE)

Phase 6 detailed plan · vsce platform-specific vsix + GitHub Actions matrix + lifecycle observability · 마스터 계획 docs/plans/vscode-md-review-plan.md 분해본 · 2026-05-15 작성

1. 개요

본 phase는 마지막 단계로, P0~P5까지 완성된 plugin을 vsce CLI로 platform-specific .vsix 패키지로 빌드하고 GitHub Actions matrix workflow로 5개 plat의 일괄 빌드 + smoke 검증을 자동화한다. node-pty native binary가 plat별로 다르므로 단일 vsix가 아닌 5개 vsix (darwin-arm64 / darwin-x64 / linux-x64 / linux-arm64 / win32-x64)를 산출한다. DELIBERATE 모드로 진행하여 pre-mortem 3 시나리오 + 확장 test plan을 명시한다 (P1과 동일 high-risk surface).

Goalvsce platform-specific vsix 5개 산출 + 각 vsix에 node-pty native binary 포함 검증 + GitHub Actions matrix CI 통과 + smoke test (@vscode/test-electron) + macOS GUI launch 함정 README 명시.
Side / Outmarketplace publish (별도 권한), GitHub Releases 자동화 (P6+1 ticket), icon 디자인 (placeholder OK), 다국어 README (영어 단일).
Scope (in)@vscode/vsce devDep, package.json marketplace 메타, README/CHANGELOG/LICENSE, .vscodeignore 정비, activate/deactivate 로깅 11 events, Windows 1809+ OS 가드, GitHub Actions matrix workflow, vsce package 5개 target, vsix 내 node-pty.node 포함 검증, npm test 회귀.
Scope (out)marketplace 실제 게시(publisher 인증 별도), icon 디자인, F-1~F-5 future features, P0.5 sudo tcpdump (별도 협조).

2. RALPLAN-DR 요약

2.1 Principles (4~5)

  1. Platform abi 고정 — node-pty native binary는 Electron 버전과 정확히 일치해야 한다. vsce platform-specific으로 abi mismatch를 사전 차단. install-time rebuild는 user 환경 오염 위험으로 금지.
  2. 설치 단순성 — 사용자는 단일 .vsix 파일 하나만 받아 설치. 별도 npm install, 별도 빌드 도구, 별도 권한 요구 없음.
  3. cost-guard 정신 유지 — P4의 이중 화이트리스트는 패키지 빌드 단계에서도 회귀 검증. cost-guard 정적 grep을 CI에 박는다.
  4. 관측성 우선 — 11 lifecycle events를 OutputChannel에 구조화 로깅하여 사용자/개발자가 production 문제 진단 가능. silent failure 0건.
  5. 한국어/한자 정책 일관 — 사용자 visible 문자열은 한국어, 코드/문서/메타데이터는 영어. 한자 일절 금지. CI grep으로 회귀 차단.

2.4 선택 근거

채택: Option A (vsce platform-specific vsix) D1(설치 실패 0%)가 critical이므로 abi 고정이 불가피하다. Option B는 user 환경 오염으로 D1을 정면 위반. Option C는 P6 scope 초과로 후속 ticket. Option A는 5 vsix 관리 부담이 있지만 CI matrix로 자동화 가능하며 marketplace 표준 패턴이므로 향후 Option C(publish)로 이행 시 그대로 호환된다.

3. Pre-mortem (DELIBERATE) — 3 시나리오

P6는 high-risk 표면이다. 출하 후 사용자가 마주칠 가능성이 높은 실패 시나리오를 사전에 정의하고 대응책을 plan에 박아둔다.

시나리오 P6-A — macOS arm64 user dlopen 실패 macOS Apple Silicon 사용자가 plugin 설치 후 첫 submit 시 node-pty.node dlopen failed로 spawn 실패. 원인: Electron abi와 prebuilt node-pty binary 불일치.
대응: (1) vsce package --target darwin-arm64으로 plat 한정 빌드 → 정확한 abi binary만 동봉. (2) CI matrix에 darwin-arm64 runner 포함하여 install + smoke 자동 검증. (3) install-time rebuild hook은 user 환경 오염 + 실패율 ↑이므로 명시적으로 사용 안 함.
시나리오 P6-B — Windows Win10 1809 미만에서 ConPTY 실패 Windows 사용자(특히 Win10 1803/1709 enterprise)가 spawn 시 ConPTY API not found 에러. 원인: ConPTY는 Win10 1809+.
대응: (1) package.json README에 "Windows 10 1809+ 또는 Win11" 명시. (2) activate 시점에 os.release()으로 OS 버전 체크. Win10 1809 미만이면 showErrorMessage로 친절한 안내(설치는 차단하지 않으나 동작 보장 안 됨 안내). (3) win32-x64 CI runner를 Windows Server 2022 (1809 호환) 사용.
시나리오 P6-C — 사용자 settings로 cost-guard 우회 사용자가 mdReview.providers.claude.args = ["-p"] 같은 직접 settings 주입으로 비대화형 호출 강제, 결과적으로 종량 과금 발생.
대응: (1) P4의 이중 화이트리스트(ALLOWED_COMMAND_BASENAMES + ALLOWED_ARGS)가 런타임에 args를 검증 → throw + OutputChannel에 args-whitelist-violation 구조화 로깅. (2) CI에 grep -rE '"-p"|"--print"' src/ 정적 검증(cost-guard). (3) README에 "args 화이트리스트로 enforced, 우회 불가" 명시.
시나리오 P6-D (추가) — macOS GUI launch zshrc 미로드 macOS user가 Finder/Dock 더블클릭으로 VSCode 실행 → login shell이 아니라 ~/.zshrc의 PATH가 미로드 → claude 바이너리 미발견 → ENOENT.
대응: README의 "macOS GUI launch" 섹션에 (1) settings에 절대 경로 지정 ("command": "/Users/foo/.local/bin/claude"), (2) VSCode를 터미널에서 code .로 실행, (3) ~/Library/LaunchAgents plist로 env 주입 — 3가지 해법 모두 명시.

6.3 src/extension.ts — activate + OS guard

import * as vscode from 'vscode';
import { release } from 'os';
import { MarkdownReviewEditor } from './editor/MarkdownReviewEditor';

export function activate(context: vscode.ExtensionContext): void {
  const lifecycle = vscode.window.createOutputChannel('mdReview-lifecycle');
  const info = `[mdReview] activate version=${context.extension.packageJSON.version} `
             + `vscode=${vscode.version} platform=${process.platform} arch=${process.arch}`;
  lifecycle.appendLine(info);

  // Windows 1809 (build 17763) 가드
  if (process.platform === 'win32') {
    const rel = release(); // "10.0.17763" 형태
    const build = parseInt(rel.split('.')[2] ?? '0', 10);
    if (build < 17763) {
      lifecycle.appendLine(`[mdReview] os-guard-violation win32 build=${build} (1809+ required for ConPTY)`);
      void vscode.window.showWarningMessage(
        'mdReview는 Windows 10 1809(build 17763) 이상이 필요합니다. 현재 빌드에서는 PTY 호출이 실패할 수 있습니다.',
      );
    }
  }

  context.subscriptions.push(
    vscode.window.registerCustomEditorProvider(
      MarkdownReviewEditor.viewType,
      new MarkdownReviewEditor(context),
      { webviewOptions: { retainContextWhenHidden: true } },
    ),
    lifecycle,
  );
}

export function deactivate(): void {
  // 별도 정리 없음 — subscriptions이 자동 dispose
}

10. Risks & Mitigations

#위험가능성영향완화
R6-1 vsce가 transitive deps 빌드 시 native module rebuild 실패 중 높음 local에서 npx vsce package --target darwin-arm64로 dry-run. 실패 시 vsce ls로 포함 파일 검사, --no-dependencies 옵션 검토.
R6-2 GitHub Actions matrix runner OS image deprecation 낮 중 matrix include 행마다 OS version 명시 (macos-14, macos-13, ubuntu-22.04, windows-2022). dependabot으로 image bump 추적.
R6-3 linux-arm64 runner 가용성 낮음 (GitHub-hosted) 중 낮 linux-arm64는 self-hosted 또는 ubuntu-22.04-arm 검토. 가용성 부재 시 P6는 4 plat로 출하 (linux-arm64는 future).
R6-4 README 영어로 작성하면서 한국어 사용자 경험 저하 중 낮 P6는 영어 README 단일. 향후 README.ko.md 추가 검토 (future ticket). 사용자 visible UI 문자열은 코드에서 한국어 유지.
R6-5 node-pty prebuild이 새 Node/Electron major에서 깨짐 중 높음 engines.vscode = "^1.90.0" 고정. node-pty 버전도 lockfile로 고정. major bump 시 별도 phase.
R6-6 vsix 크기 비대 (10MB+, marketplace 100MB 한도는 여유) 낮 낮 .vscodeignore로 test/, docs/, .omc/, source map 제외. vsce ls로 산출 전 점검.
R6-7 publisher 미인증으로 vsix가 "unverified publisher" 경고 높 낮 P6 범위는 local install (.vsix 직접 배포). marketplace publish + verified publisher 인증은 Option C future ticket.
