P2 — 코멘트 데이터 모델 + 영속화

Phase 2 detailed plan · Comment Model & Persistence · 마스터 계획 docs/plans/vscode-md-review-plan.md 분해본 · 2026-05-15 작성

1. 개요

본 phase는 마크다운 리뷰 코멘트(suggestion, question)를 표현하는 도메인 모델과 그 영속화 계층을 구현한다. P3 WebView가 코멘트를 화면에 그리고, P4 PromptBuilder가 LLM에 송신할 코멘트 목록을 직렬화하기 위한 데이터 기반을 마련한다.

GoalComment 엔티티, CommentStore CRUD API, SidecarPersistence(.md.review.json) 및 WorkspaceStatePersistence(VSCode Memento)를 구현하고 round-trip 회귀 테스트로 검증한다.
Side / OutWebView UI, 사이드 panel 렌더링, LLM 호출, diff 적용은 본 phase 범위 외. 본 phase는 데이터 계층만.
Scope (in)도메인 타입, zod 스키마, 두 영속화 백엔드, 메모리 내 immutable CRUD, 단위 테스트, 한자 정적 검증.
Scope (out)WebView 인터랙션, AnchorResolver(P3 소관), 코멘트 정렬/필터 UX, multi-document 통합 관리.

본 phase의 위치 P2는 P3 WebView와 P4 PromptBuilder의 입력 데이터 계약을 확정한다. 따라서 도메인 모델 결정과 영속화 포맷은 후속 phase의 직렬화 비용에 직접 영향한다. 본 phase에서 한 번 잘못 결정하면 P3~P5 전체에 회귀가 전파되므로 schema는 보수적으로 잡고 zod로 강제한다.

2. RALPLAN-DR 요약

2.1 Principles (3~5)

  1. Immutability first — 모든 CRUD 연산은 새 배열/객체를 반환한다. 입력 array reference는 변하지 않는다. React 친화 패턴이며 P3 WebView 재렌더 트리거를 단순화한다.
  2. Schema-as-contract — 사이드카 파일은 zod로 parse하며 schema 위반 시 throw한다. 사용자가 손으로 편집할 수 있으므로 schema는 readiness gate 역할을 한다.
  3. Single source of truth per document — 한 .md 문서당 하나의 영속화 backend만 활성 (mutually exclusive). 자동 fallback 없음. R-9(실수 commit) 위험은 사용자가 명시적으로 선택한 backend에 한해 발생.
  4. Test-first round-trip — 모델 직렬화 → 디스크 write → 디스크 read → 모델 deep-equal이 통과해야 phase가 종료된다. 측정 가능한 종료 조건은 모두 grep 또는 mocha assert로 검증 가능한 형태로 작성.

2.2 Decision Drivers (Top 3)

#Driver설명
D1 P3 WebView 재렌더 효율 WebView는 코멘트 목록 변화 시 selective re-render가 필요하다. 입력 array가 mutated되면 React/diff 알고리즘이 변경을 감지하지 못하거나 over-render한다. 따라서 immutable CRUD가 필수.
D2 사용자 수동 편집 안전성 .md.review.json 사이드카는 사용자가 git diff로 보거나 직접 편집 가능하다. 잘못된 JSON 또는 schema 위반이 silently 받아들여지면 P3 UI가 깨진다. zod로 명시적 parse하고 실패 시 한국어 에러로 알림.
D3 2개 backend mutually exclusive 사이드카와 workspaceState 둘 다 활성화하면 어느 것을 우선할지 모호하다. R-9 위험(사이드카 git commit) 회피를 위해 workspaceState를 secondary backend로 제공하되, settings로 한쪽만 선택하도록 강제. priority logic 없음.

2.3 Viable Options (≥2 비교)

옵션설명ProsCons
A. 사이드카 파일(.md.review.json) 선택 각 .md 파일 옆에 동명 .md.review.json 사이드카를 두고 zod 스키마로 직렬화. git friendly, portable, 사용자가 직접 검사 가능, 다른 도구와 상호운용 가능 실수로 commit 위험(R-9), 파일 시스템 race condition 가능성, atomic write 필요
B. VSCode WorkspaceState (Memento) secondary VSCode ExtensionContext.workspaceState에 key=docUri로 저장. 사용자가 git에 commit할 위험 없음, VSCode가 관리하므로 atomic, 파일 시스템 의존성 0 portability 없음 (다른 머신·다른 IDE에서 사라짐), VSCode 외 도구가 읽을 수 없음, 디버깅 어려움
C. 본문 안 HTML 주석으로 매립 <!-- comment:{...} --> 형태로 .md 본문에 직접 삽입. 단일 파일, 추가 파일 0개 본문 dirty, AnchorResolver가 코멘트 텍스트를 본문으로 오인할 위험, P5 diff가 코멘트 주석까지 비교 대상에 포함
D. SQLite 워크스페이스 단위 단일 DB 파일. 쿼리 가능, multi-document 통합 관리 용이 1.5d phase 범위 초과, native binding 의존성(node-pty와 같은 ABI 이슈 재발 위험), 사용자가 직접 편집 불가

2.4 선택 근거

Primary: A(Sidecar), Secondary: B(WorkspaceState) — mutually exclusive A는 git 친화적이고 portable하다는 결정적 장점이 있어 default로 채택한다. R-9(실수 commit) 위험은 README에 .gitignore 권장 패턴을 명시하여 완화한다. 그러나 사이드카가 부담스러운 사용자(예: 본문만 commit하고 코멘트는 로컬에만 두고 싶은 경우)를 위해 B를 secondary backend로 제공한다. 두 backend를 동시 활성화하면 어느 것이 권위 있는지 모호하므로 settings의 mdReview.persistenceBackend로 한쪽만 선택하도록 강제한다 (mutually exclusive). 자동 fallback이나 우선순위 로직은 두지 않는다 — 사용자 명시적 선택만 인정. C는 본문 dirty 문제로 즉시 기각. D는 phase 범위 초과 + 의존성 부담으로 기각하되 multi-document 통합 관리가 필요해지면 후속 phase로 재검토.

3. Day-by-Day Work Package

Day 1 — Comment 모델 + Sidecar 영속화

예상 소요 1.0 작업일 · 산출물 5개 · 단위 테스트 3종 그룹

목표

Comment 도메인 타입을 확정하고 zod 스키마를 동일 파일에서 export한다. SidecarPersistence를 구현하여 .md.review.json 파일 단위 round-trip이 동작함을 확인한다. atomic write 패턴(임시 파일 → rename)을 도입하여 partial write로 인한 corruption을 차단한다.

산출물

  • src/model/Comment.ts — Comment interface + CommentSchema(zod) + CommentsFileSchema(파일 wrapper) + CommentType, CommentAnchor 보조 타입
  • src/store/PersistenceBackend.ts — load(docUri): Promise<Comment[]> / save(docUri, comments): Promise<void> 인터페이스 선언 (두 백엔드의 공통 계약)
  • src/store/SidecarPersistence.ts — PersistenceBackend 구현, fs/promises 기반, atomic write
  • test/store/SidecarPersistence.test.ts — round-trip, schema 실패, atomic 검증, 없는 파일 read 케이스
  • src/store/sidecarPath.ts — computeSidecarPath(docUri): string 유틸 (URI → ${path}.review.json)

OMC 위임

본 day의 코드 작성은 main thread에서 직접 수행. 작성 완료 후 code-reviewer agent에 별도 lane으로 리뷰 위임 (자기 자신을 같은 컨텍스트에서 approve 금지 규약).

기술 노트

  • Atomic write 패턴: writeFile(path + '.tmp', data) → rename(path + '.tmp', path). rename은 POSIX에서 atomic. 동일 파일 시스템 내에서만 atomic 보장이므로 .tmp 파일은 사이드카와 동일 디렉토리에 둔다.
  • 없는 파일 read: ENOENT 시 빈 배열 반환 (사이드카가 아직 없는 신규 문서는 정상 케이스). 그 외 errno는 throw.
  • JSON parse 실패: SyntaxError 발생 시 한국어 에러로 wrap (사이드카 JSON parse 실패: ${path}).
  • Schema 위반: zod의 safeParse를 사용하여 success: false 시 issues를 사람이 읽을 수 있는 한국어 메시지로 변환 (P4 OutputChannel과 동일 패턴).
  • Encoding: utf-8 명시. BOM은 작성하지 않음. EOL은 LF.
  • Pretty print: JSON.stringify(data, null, 2) + 끝에 LF 1개. 사용자가 git diff로 가독성 있게 보기 위함.

측정 가능한 종료 조건

  • npm test -- --grep SidecarPersistence exit code 0 (4개 이상 it 블록)
  • Round-trip: const c = sample(); await save(uri, [c]); const r = await load(uri); expect(r).to.deep.equal([c]) 통과
  • 없는 파일 load: const r = await load(nonExistent); expect(r).to.deep.equal([]) 통과
  • Schema 실패: writeFileSync(uri+'.review.json', '{"version":99}') 후 load → throws assert
  • Atomic write: save 중간에 임의 throw → 원본 파일 unchanged 확인 (fs.readFileSync 값 비교)
  • 한자 정적 검증: ! grep -rP '[\x{4E00}-\x{9FFF}]' src/model src/store exit code 0
  • npm run compile exit code 0
  • npm run lint exit code 0 (cost-guard 포함)

Day 1.5 — CommentStore 핵심 + WorkspaceStatePersistence

예상 소요 0.5 작업일 · 산출물 3개 · 단위 테스트 2종 그룹 + 통합 1종

목표

도메인 계층(CommentStore)을 추가하여 immutable CRUD API를 제공하고, P3가 의존할 안정적인 인터페이스를 확정한다. WorkspaceStatePersistence를 두 번째 backend로 구현하고 동일한 round-trip 회귀 테스트를 통과시킨다. 두 backend가 PersistenceBackend 인터페이스를 통해 interchangeable한지 검증한다.

산출물

  • src/store/CommentStore.ts — load(docUri) / save(docUri, comments) / add(comments, draft) / update(comments, id, patch) / remove(comments, id) / list(comments) — 모두 pure function 또는 backend 위임
  • src/store/WorkspaceStatePersistence.ts — PersistenceBackend 구현, VSCode Memento 의존성 주입
  • src/store/PersistenceBackendFactory.ts — settings의 mdReview.persistenceBackend를 읽어 적절한 backend instance 반환 (mutually exclusive 강제)
  • test/store/CommentStore.test.ts — immutability, CRUD 6종, id 충돌 케이스
  • test/store/WorkspaceStatePersistence.test.ts — Memento mock으로 round-trip + key naming 검증
  • test/store/PersistenceBackend.contract.test.ts — 두 backend를 동일 contract suite로 검증 (interchangeability)

OMC 위임

본 day 끝에 code-reviewer agent 별도 lane spawn — 본 phase 전체(Day 1 + Day 1.5)를 한 번에 리뷰. 발견된 이슈가 있으면 본 phase 안에서 수정 후 종료 조건 재검증.

기술 노트

  • CRUD signature: add, update, remove는 pure function으로 새 배열 반환. load, save는 backend 위임(side effect). 분리 이유는 단위 테스트에서 backend mock 없이 CRUD 자체를 검증하기 위함.
  • ID 생성: add 호출 시 id가 비어 있으면 node:crypto.randomUUID()로 생성. caller가 id를 명시하면 그대로 사용 (P3에서 optimistic update 시 client-side id 제공). 중복 id는 add가 throws.
  • Update patch 의미: update(comments, id, patch)는 {...comment, ...patch, updatedAt: new Date().toISOString()}. id와 createdAt은 patch로 변경 불가 (TypeScript Omit로 강제).
  • WorkspaceState key: mdReview.comments.${docUriString} 형태. URI는 vscode.Uri.toString() 결과를 그대로 사용 (경로 정규화 책임을 VSCode에 위임).
  • WorkspaceState size 한계: VSCode Memento는 큰 페이로드에 부적합 (key당 권장 수 KB). 코멘트 수가 많아지면 사이드카로 전환할 것을 README에 명시.
  • Backend factory: PersistenceBackendFactory.create(config)가 config.persistenceBackend === 'sidecar' ? new SidecarPersistence() : new WorkspaceStatePersistence(memento) 분기. 잘못된 값은 zod에서 사전 거부.

측정 가능한 종료 조건

4. Architecture Diagram

P2 데이터 계층 — 모듈 의존도 +-------------------------------------------------------------+ | P3 WebView (다음 phase) | | (CustomTextEditor + inline overlay) | +------------------------------+------------------------------+ | v (use) +-------------------------------------------------------------+ | CommentStore | | load() save() add() update() remove() list() | | (pure function CRUD + backend 위임 load/save) | +------+---------------------------------------------+--------+ | | v (PersistenceBackend 인터페이스) v +------------------------+ +------------------------+ | SidecarPersistence | | WorkspaceStatePersist | | .md.review.json | | ExtensionContext | | (default) | | .workspaceState | | | | (secondary, opt-in) | +-----------+------------+ +------------+-----------+ | | v v +------------------------+ +------------------------+ | fs/promises | | VSCode Memento API | | writeFile/readFile | | get/update | | rename (atomic) | | | +------------------------+ +------------------------+ +-------------------------------------------------------------+ | Comment 도메인 모델 | | interface Comment { id, type, anchor, before?, after?, | | note?, createdAt, updatedAt? } | | CommentSchema (zod), CommentsFileSchema (file wrapper) | +-------------------------------------------------------------+ [mutually exclusive 강제] PersistenceBackendFactory.create(config) ├─ config.persistenceBackend === 'sidecar' → SidecarPersistence └─ config.persistenceBackend === 'workspaceState' → WorkspaceStatePersistence (그 외 값은 zod 단계에서 reject)
핵심 invariant
  • 한 문서 단위로 backend는 1개만 활성. priority/fallback 없음.
  • CommentStore는 backend 종류를 모른다 — PersistenceBackend 인터페이스에만 의존.
  • 도메인 모델은 두 backend 모두에서 동일한 directly-serializable JSON 구조 (Memento도 JSON으로 직렬화됨).

5. Critical Code Specs

본 섹션은 의사 코드가 아니라 실제 구현에 가까운 시그니처와 핵심 분기를 명세한다. 도우미 함수는 생략하고 의미 핵심만 표기한다. 주석은 "왜 이렇게 설계했는가"에 집중한다.

5.1 src/model/Comment.ts — 도메인 모델 + zod 스키마

import { z } from 'zod';

// CommentType은 P3 inline UI의 색상/아이콘 매핑과 1:1 대응한다.
// 향후 'praise' 등을 추가할 가능성이 있어 union으로 열어두되,
// 현재는 suggestion/question 2가지로 한정한다.
export const CommentTypeSchema = z.enum(['suggestion', 'question']);
export type CommentType = z.infer<typeof CommentTypeSchema>;

// Anchor는 LSP Position과 호환되도록 0-based로 고정.
// length는 selection 길이(문자 단위). AnchorResolver(P3)가 채운다.
export const CommentAnchorSchema = z.object({
  line:   z.number().int().nonnegative(),
  col:    z.number().int().nonnegative(),
  length: z.number().int().nonnegative(),
});
export type CommentAnchor = z.infer<typeof CommentAnchorSchema>;

// Comment는 디스크 저장 형식과 메모리 표현이 동일하다 (직접 직렬화).
// before/after는 suggestion 타입에서만 의미가 있어 optional로 두지만,
// PromptBuilder(P4)가 join 시 둘 다 비어있으면 그 코멘트는 prompt에서 제외한다.
export const CommentSchema = z.object({
  id:        z.string().min(1),
  type:      CommentTypeSchema,
  anchor:    CommentAnchorSchema,
  before:    z.string().optional(),
  after:     z.string().optional(),
  note:      z.string().optional(),
  createdAt: z.string().datetime(),
  updatedAt: z.string().datetime().optional(),
});
export type Comment = z.infer<typeof CommentSchema>;

// 파일 wrapper는 version 필드로 schema 진화를 지원한다.
// 현재 version은 1. 향후 마이그레이션 시 version 분기 추가 예정.
export const COMMENTS_FILE_VERSION = 1 as const;
export const CommentsFileSchema = z.object({
  version:  z.literal(COMMENTS_FILE_VERSION),
  comments: z.array(CommentSchema),
});
export type CommentsFile = z.infer<typeof CommentsFileSchema>;

// add 단계에서 사용되는 draft 타입 — id/createdAt은 store가 채움.
export type CommentDraft = Omit<Comment, 'id' | 'createdAt' | 'updatedAt'> & { id?: string };

// update 단계에서 사용되는 patch 타입 — id/createdAt은 변경 불가.
export type CommentPatch = Partial<Omit<Comment, 'id' | 'createdAt' | 'updatedAt'>>;

5.2 src/store/SidecarPersistence.ts — 사이드카 파일 영속화

import { promises as fs } from 'fs';
import { dirname, basename, join } from 'path';
import { fileURLToPath } from 'url';
import {
  CommentsFileSchema, COMMENTS_FILE_VERSION,
  type Comment, type CommentsFile,
} from '../model/Comment';
import { type PersistenceBackend } from './PersistenceBackend';

// 사이드카 경로 계산을 별도 함수로 분리하여 단위 테스트 가능하게 함.
// docUri는 file:// 스킴 또는 절대 경로 문자열 둘 다 지원.
export function computeSidecarPath(docUri: string): string {
  const p = docUri.startsWith('file://') ? fileURLToPath(docUri) : docUri;
  return `${p}.review.json`;
}

export class SidecarPersistence implements PersistenceBackend {
  readonly backendName = 'sidecar' as const;

  async load(docUri: string): Promise<Comment[]> {
    const path = computeSidecarPath(docUri);
    let raw: string;
    try {
      raw = await fs.readFile(path, 'utf-8');
    } catch (err: unknown) {
      // ENOENT는 신규 문서 정상 케이스 — 빈 배열 반환.
      // 그 외 (권한, I/O 에러)는 의도된 throw로 caller에 전달.
      if (isENOENT(err)) return [];
      throw err;
    }

    let parsed: unknown;
    try {
      parsed = JSON.parse(raw);
    } catch (e: unknown) {
      throw new Error(`사이드카 JSON parse 실패: ${path}`);
    }

    const result = CommentsFileSchema.safeParse(parsed);
    if (!result.success) {
      // zod issue를 사람이 읽을 수 있는 한국어 메시지로 정리.
      const issues = result.error.issues
        .map(i => `  - ${i.path.join('.')}: ${i.message}`)
        .join('\n');
      throw new Error(`사이드카 schema 검증 실패 (${path}):\n${issues}`);
    }
    return result.data.comments;
  }

  async save(docUri: string, comments: readonly Comment[]): Promise<void> {
    const path = computeSidecarPath(docUri);
    const file: CommentsFile = {
      version: COMMENTS_FILE_VERSION,
      comments: [...comments],
    };
    const serialized = JSON.stringify(file, null, 2) + '\n';

    // Atomic write: 같은 디렉토리에 .tmp 파일을 쓴 뒤 rename으로 교체.
    // 같은 파일 시스템 안에서 rename은 POSIX atomic이므로
    // 도중에 프로세스가 죽어도 원본은 corrupt되지 않는다.
    const tmp = `${path}.${randomSuffix()}.tmp`;
    await fs.writeFile(tmp, serialized, { encoding: 'utf-8' });
    await fs.rename(tmp, path);
  }
}

function isENOENT(err: unknown): boolean {
  return typeof err === 'object' && err !== null && (err as { code?: string }).code === 'ENOENT';
}

function randomSuffix(): string {
  return Math.random().toString(36).slice(2, 8);
}

5.3 src/store/WorkspaceStatePersistence.ts — VSCode Memento 영속화

import {
  CommentSchema, type Comment,
} from '../model/Comment';
import { z } from 'zod';
import { type PersistenceBackend } from './PersistenceBackend';

// Memento를 직접 import하지 않고 인터페이스로 추상화하여
// 단위 테스트에서 fake 객체로 주입 가능하게 함.
export interface MementoLike {
  get<T>(key: string): T | undefined;
  update(key: string, value: unknown): Thenable<void>;
}

type Thenable<T> = Promise<T> | { then: (resolve: (v: T) => void) => void };

const StoredCommentsSchema = z.array(CommentSchema);

export class WorkspaceStatePersistence implements PersistenceBackend {
  readonly backendName = 'workspaceState' as const;

  constructor(private readonly memento: MementoLike) {}

  async load(docUri: string): Promise<Comment[]> {
    const key = computeKey(docUri);
    const raw = this.memento.get<unknown>(key);
    if (raw === undefined) return [];

    const result = StoredCommentsSchema.safeParse(raw);
    if (!result.success) {
      throw new Error(
        `workspaceState 코멘트 schema 검증 실패 (key=${key}): ${result.error.message}`
      );
    }
    return result.data;
  }

  async save(docUri: string, comments: readonly Comment[]): Promise<void> {
    const key = computeKey(docUri);
    // Memento의 update는 JSON 직렬화 가능한 값만 허용.
    // Comment 타입은 모두 primitive/string이므로 안전.
    await Promise.resolve(this.memento.update(key, [...comments]));
  }
}

function computeKey(docUri: string): string {
  // docUri는 vscode.Uri.toString() 결과를 그대로 사용.
  // 경로 정규화 책임은 VSCode에 위임 (file:///foo == file:///foo는 VSCode가 보장).
  return `mdReview.comments.${docUri}`;
}

5.4 src/store/CommentStore.ts — Immutable CRUD 핵심

import { randomUUID } from 'crypto';
import {
  type Comment, type CommentDraft, type CommentPatch,
} from '../model/Comment';
import { type PersistenceBackend } from './PersistenceBackend';

// CommentStore는 두 책임을 가진다:
//   1) Pure function CRUD (add/update/remove/list) — backend 비의존
//   2) Backend 위임 (load/save) — disk/memento I/O
// 분리 이유: CRUD 자체는 backend mock 없이 단위 테스트 가능해야 함.
export class CommentStore {
  constructor(private readonly backend: PersistenceBackend) {}

  async load(docUri: string): Promise<Comment[]> {
    return this.backend.load(docUri);
  }

  async save(docUri: string, comments: readonly Comment[]): Promise<void> {
    return this.backend.save(docUri, comments);
  }

  // Pure: 새 배열 반환, 입력 array reference 변경 없음.
  add(comments: readonly Comment[], draft: CommentDraft): Comment[] {
    const id = draft.id ?? randomUUID();
    if (comments.some(c => c.id === id)) {
      throw new Error(`코멘트 id 충돌: ${id}`);
    }
    const now = new Date().toISOString();
    const created: Comment = {
      ...draft,
      id,
      createdAt: now,
    };
    return [...comments, created];
  }

  // Pure: id로 찾아 patch 병합. createdAt은 보존, updatedAt 갱신.
  update(
    comments: readonly Comment[],
    id: string,
    patch: CommentPatch,
  ): Comment[] {
    const idx = comments.findIndex(c => c.id === id);
    if (idx === -1) {
      throw new Error(`코멘트를 찾을 수 없음: id=${id}`);
    }
    const next: Comment = {
      ...comments[idx],
      ...patch,
      id: comments[idx].id,
      createdAt: comments[idx].createdAt,
      updatedAt: new Date().toISOString(),
    };
    return [...comments.slice(0, idx), next, ...comments.slice(idx + 1)];
  }

  // Pure: id 일치 항목 제거. 없으면 throw (idempotent하지 않음).
  // 이유는 P3 UI가 사용자 확인 후 명시적으로 remove하기 때문에 silent miss를 막아야 함.
  remove(comments: readonly Comment[], id: string): Comment[] {
    const next = comments.filter(c => c.id !== id);
    if (next.length === comments.length) {
      throw new Error(`삭제할 코멘트를 찾을 수 없음: id=${id}`);
    }
    return next;
  }

  // list는 의도적으로 readonly 사본을 반환 — caller가 외부에서 mutate 하지 못하게 보호.
  list(comments: readonly Comment[]): readonly Comment[] {
    return [...comments];
  }
}

5.6 src/store/PersistenceBackendFactory.ts — Mutually exclusive 강제

import { z } from 'zod';
import { SidecarPersistence } from './SidecarPersistence';
import {
  WorkspaceStatePersistence, type MementoLike,
} from './WorkspaceStatePersistence';
import { type PersistenceBackend } from './PersistenceBackend';

export const PersistenceBackendKindSchema = z.enum(['sidecar', 'workspaceState']);
export type PersistenceBackendKind = z.infer<typeof PersistenceBackendKindSchema>;

export interface PersistenceBackendFactoryDeps {
  memento: MementoLike;
}

// settings에서 두 값이 동시에 truthy인 경우는 zod enum이 사전 거부.
// 잘못된 값 ('both', 'auto' 등)도 enum 검증에서 throw.
// priority/fallback 로직은 도입하지 않는다 — 사용자 명시적 선택만 인정.
export function createPersistenceBackend(
  kind: PersistenceBackendKind,
  deps: PersistenceBackendFactoryDeps,
): PersistenceBackend {
  const validated = PersistenceBackendKindSchema.parse(kind);
  switch (validated) {
    case 'sidecar':
      return new SidecarPersistence();
    case 'workspaceState':
      return new WorkspaceStatePersistence(deps.memento);
    default: {
      // exhaustive switch — 새 backend 추가 시 컴파일 에러로 누락 방지.
      const _exhaustive: never = validated;
      throw new Error(`알 수 없는 persistence backend: ${_exhaustive}`);
    }
  }
}

6. ADR 운영화

마스터 계획서 § ADR과 정합되도록 본 phase의 결정 사항을 정책으로 운영화한다.

마스터 ADR 항목P2에서의 적용
AD-1: 데이터 모델은 client/server interchangeable JSON Comment 타입을 메모리/디스크/Memento 모두 동일 구조로 정의. 비직렬화 가능한 필드(Date 인스턴스 등) 금지. createdAt은 ISO 8601 문자열로 통일.
AD-2: 영속화 backend는 명시적 선택 (mutually exclusive) PersistenceBackendFactory가 zod enum으로 강제. priority/fallback 없음. settings 변경은 reload 후에만 반영 (P4 ProviderConfig와 동일 패턴).
AD-3: 모든 외부 입력은 zod로 검증 사이드카 파일과 Memento 값 모두 safeParse로 검증. schema 실패는 한국어 에러로 wrap.
AD-4: Immutability는 React 친화 표현 모든 CRUD는 새 배열 반환. readonly Comment[] 타입으로 caller도 mutate 불가하게 강제.
AD-5: VSCode API는 의존성 주입으로 추상화 Memento를 MementoLike 인터페이스로 wrap. 단위 테스트에서 fake 객체로 주입 가능.
운영화 효과 위 ADR을 본 phase에서 강제함으로써 P3 WebView 측에서 다음을 가정할 수 있다: (a) CommentStore가 던지는 객체는 zod 검증 통과 후 반환된 것이므로 추가 validation 불필요, (b) 모든 CRUD는 새 배열 reference를 반환하므로 React/diff 알고리즘이 변화를 감지 가능, (c) 두 backend의 동작은 동일 contract suite로 검증되었으므로 backend 종류와 무관하게 동작 보장.

7.4 Schema 진화 정책

마이그레이션 전략 (현재 미적용, 미래 대비 명시)
  • v1 → v2 진화 시: load 단계에서 version 분기를 두고 v1 객체를 v2로 변환. 변환 직후 디스크에 v2로 save (자동 migration).
  • Breaking change(필드 삭제, 타입 변경)는 새 version으로 분리. 동일 version 안에서는 backward compatible field 추가만.
  • v2 이상의 backend에서 v1 사이드카를 만나면 warning 로그 + 자동 migration.
  • 본 phase 범위: v1만 구현. migration 로직은 후속 phase 진입 조건에 포함.

#위험가능성영향완화책임

P2-R-4 WorkspaceState key가 docUri 변경(파일 이동/rename)에 대응하지 못함 중 중 본 phase 범위 외 — VSCode의 workspace.onDidRenameFiles를 P3에서 hook하여 key 마이그레이션 처리. P2는 key 형식만 안정화하여 P3가 이를 활용할 수 있도록 함. P2 (계약), P3 (rename 핸들러)
P2-R-5 zod schema 버전 진화 시 backward compatibility 깨짐 낮음 중 version 필드를 file wrapper에 두고 load 단계에서 version 분기 도입(현재는 v1만). breaking change는 새 version으로만. AC-4 schema 진화 정책(§ 7.4) 준수. P2 + 후속 phase
P2-R-6 임시 파일(.tmp) leak — atomic write 도중 프로세스 kill되면 .tmp가 남음 낮음 낮음 random suffix를 붙여 충돌 방지. cleanup은 best-effort (도중 죽으면 다음 save 때 새 suffix로 재시도). README에 trailing .tmp 발견 시 수동 삭제 가능 명시. P2
P2-R-7 UTF-16 col 단위 vs 사용자 표시 col 차이 (서로게이트 쌍, emoji) 낮음 중 P2는 AnchorResolver(P3 소관)에서 발생할 이슈를 데이터 계약 차원에서만 받아들임. col은 "VSCode가 보고하는 col 단위 그대로 저장"으로 명시. 변환은 P3가 책임. P3
마스터 Risk Register와의 정합 P2-R-1은 마스터 R-9의 본 phase 운영화이다. 마스터 Risk Register의 다른 항목(R-1~R-16)은 본 phase 책임 범위 외이며, P1(PTY 코어) 봉인 시 또는 P3~P6에서 운영화된다.
