P3 — 마크다운 리뷰 WebView (Review Editor UI)

Phase 3 detailed plan · CustomTextEditor + markdown-it + inline overlay + comment panel · 마스터 계획 docs/plans/vscode-md-review-plan.md 분해본 · 2026-05-15 작성

1. 개요

본 phase는 사용자가 마크다운 본문을 시각적으로 보고, 임의 텍스트 구간을 선택하여 suggestion/question 코멘트를 인라인으로 부착할 수 있는 UI를 구현한다. P2 데이터 계층(CommentStore, Comment)을 화면에 binding하고, P4 제출 흐름에 필요한 [제출] 버튼 트리거 지점도 본 phase에서 마련한다.

GoalCustomTextEditorProvider 기반 마크다운 리뷰 에디터를 띄우고, markdown-it 렌더링 + 선택 구간 anchor 부착 + 사이드 panel 코멘트 목록 + [제출] 버튼 UI를 구현한다. P2 영속화와 round-trip 통합 회귀를 통과한다.
Side / Out실제 LLM 호출(P4), diff 적용(P5)은 본 phase 범위 외. [제출] 버튼은 placeholder 메시지만 발화하고 P4가 hook한다.
Scope (in)CustomTextEditor 등록, WebView HTML/CSS/JS, markdown-it 렌더, anchor 선택→저장, 패널 목록 렌더링, anchor 클릭→하이라이트, P2 CommentStore wiring, postMessage contract, CSP, AnchorResolver 단위 테스트.
Scope (out)LLM 호출, PromptBuilder, diff editor, sentinel 처리, 코멘트 검색/필터/정렬 UX 고도화, 다중 문서 동시 리뷰.

본 phase의 위치 P3는 사용자가 처음으로 시각적으로 산출물을 인지하는 단계이다. 따라서 본 phase는 F5 디버그 + 스크린샷 형식의 수동 검증이 필수이며, 자동 테스트는 AnchorResolver(line/col 계산), 메시지 contract(zod schema), WebViewBridge(postMessage adapter) 같은 분리 가능 단위만 대상으로 한다.

2. RALPLAN-DR 요약

2.1 Principles (4)

  1. Single source of truth는 Extension Host — 마크다운 본문과 코멘트 권위 사본은 Extension Host에 둔다. WebView는 렌더링 view일 뿐이며, anchor 정보와 partial 코멘트 payload만 받는다. 본문 전체는 절대 WebView로 직렬화 송신하지 않는다 (R-5 완화 핵심).
  2. Message는 zod로 양쪽 검증 — Extension Host → WebView, WebView → Extension Host 양방향 메시지를 zod schema로 사전 정의하고 송수신 양단에서 parse한다. 잘못된 메시지는 silently drop하지 않고 OutputChannel에 로그 + drop.
  3. WebView는 minimal vanilla TS — Lit/Preact 같은 프레임워크 도입은 P3 phase 범위 외. 인라인 오버레이와 패널은 plain DOM API + 작은 클래스로 충분히 표현 가능. 부피와 빌드 복잡성을 낮추어 검토와 디버깅 용이성을 유지.
  4. F5 manual smoke이 회귀 방지의 1차 방어선 — UI는 자동화하기 어려우므로 매 phase 종료 시 5분짜리 F5 수동 체크리스트를 표준화하여 회귀 발생 시 즉시 발견한다.

2.2 Decision Drivers (Top 3)

#Driver설명
D1대용량 마크다운 안전성 (R-5)500KB+ 문서에서 본문 전체 직렬화는 응답 지연·메모리 폭주 위험. 본문은 Extension Host가 file system + vscode.TextDocument로만 유지하고, WebView에는 렌더링된 HTML 조각(또는 anchor 좌표 + 보조 발췌)만 전달.
D2Anchor 좌표계 일관성WebView가 보는 DOM의 selection과 Extension Host가 보는 line/col이 일치해야 한다. AnchorResolver는 두 좌표계의 brokering 책임을 단일 모듈에 집중하여 회귀를 좁은 범위에 가둔다.
D3P4 [제출] 버튼 흐름 hook 지점본 phase는 [제출] 버튼 클릭 시 submit 메시지를 Extension Host로 발화하기만 한다. 실제 LLM 호출은 P4가 수신측에서 구현. 본 phase에서 hook 지점이 안정화되어 있어야 P4가 추가 변경 없이 plugin-in 가능.

2.3 Viable Options (≥2 비교)

옵션설명ProsCons
A. CustomTextEditor + WebView 선택 CustomTextEditorProvider로 .md 파일을 직접 열고 WebView로 렌더. VSCode native 통합, 파일 열기 UX 자연스러움, 본문은 TextDocument로 동기화 자동, 우클릭 "Open with" 컨텍스트 메뉴 자동 WebView CSP 제약, postMessage 메시지 송신/수신 boilerplate, 본문 직렬화 시 R-5 위험
B. WebviewView in Side Panel + 보조 에디터 사이드바 WebView를 띄우고 본문은 별도 vscode.window.activeTextEditor로 본다. 본문은 VSCode 내장 마크다운 미리보기 기능 reuse 가능 UX 분산 (본문/패널 분리), selection ↔ anchor 매핑 어려움, "Open with" 컨텍스트 메뉴에 등록 불가
C. External Browser + WebSocket VSCode에서 localhost 브라우저를 열어 외부에서 렌더. 임의 프레임워크 사용 자유 VSCode integration zero, 사용자 onboarding 부담, 보안 surface 추가, phase 범위 초과

2.4 선택 근거

Primary: A (CustomTextEditor + WebView) VSCode native 통합과 우클릭 "Open with Markdown Review" 자연스러움이 결정적이다. R-5 위험은 본문을 WebView에 직렬화하지 않고 markdown-it으로 Extension Host 측에서 렌더한 HTML 조각만 송신하는 구조로 완화한다 (또는 추후 작은 chunk 단위 lazy load 검토). B는 selection ↔ anchor 매핑 어려움으로 기각. C는 phase 범위 초과로 기각.

3. Day-by-Day Work Package

Day 1 — MarkdownReviewEditor + WebViewBridge + AnchorResolver

예상 소요 1.0 작업일 · 산출물 5개 · 단위 테스트 3종 그룹

목표

Extension Host 측 골조를 완성한다. CustomTextEditorProvider를 등록하여 .md 파일을 "Open with Markdown Review"로 열 수 있게 하고, WebViewBridge로 postMessage 양방향 래퍼를 마련하며, AnchorResolver의 line/col 계산을 단위 테스트로 검증한다. 이 day의 산출물만으로도 F5 → .md 우클릭 → Open with → WebView 패널 열림까지 동작해야 한다.

산출물

  • src/editor/MarkdownReviewEditor.ts — CustomTextEditorProvider 구현, WebView HTML 셸 주입 (markdown-it 렌더 결과 + nonce + CSP), onDidChangeTextDocument hook으로 본문 변경 시 WebView re-render
  • src/editor/WebViewBridge.ts — postMessage(typedMessage) + onDidReceiveMessage(handler) 래퍼. 양단 zod parse 적용 + 실패 시 OutputChannel 로그 후 drop
  • src/editor/AnchorResolver.ts — resolveAnchorFromDom(dom selection info): WebView가 보낸 DOM 좌표(nodePath + offset)를 본문 line/col/length로 변환. 역변환 resolveDomFromAnchor(comment)도 제공
  • src/editor/messages.ts — HostToWebViewMessage, WebViewToHostMessage discriminated union을 zod로 정의
  • src/extension.ts 갱신 — vscode.window.registerCustomEditorProvider(MarkdownReviewEditor.viewType, new MarkdownReviewEditor(...)) 등록 + activation event 추가
  • test/editor/AnchorResolver.test.ts — line/col 계산 단위 테스트 (BOM, CRLF, 서로게이트 쌍 케이스)
  • test/editor/messages.test.ts — discriminated union zod parse 통과/실패 케이스
  • test/editor/WebViewBridge.test.ts — fake webview 객체 주입 + 메시지 parse → handler 호출 검증

OMC 위임

Day 1 끝에 자동 테스트 그린 확인 후 다음 day로 진군. 본 day 단독 code-reviewer 위임은 생략하고 Day 2.5 끝에 P3 전체 일괄 리뷰.

기술 노트

  • CustomTextEditor activation: package.json의 contributes.customEditors에 { viewType: 'mdReview.editor', displayName: 'Markdown Review', selector: [{ filenamePattern: '*.md' }] } 추가. priority는 option으로 두어 우클릭 "Open with"에서 명시적 선택 가능.
  • WebView HTML 셸: asWebviewUri로 media/webview/main.js, style.css 경로 변환. nonce는 매 open마다 randomUUID()로 재생성. CSP는 § 7 참조.
  • markdown-it 렌더 위치: Extension Host에서 본문을 markdown-it으로 렌더한 HTML 문자열을 WebView에 전달. 이유는 (a) markdown-it 의존성을 WebView에 번들링하지 않아 payload 절감, (b) 본문 변경 diff 계산 등 후속 기능에서 host 측 단일 사본이 유리.
  • onDidChangeTextDocument 디바운스: 사용자가 외부 에디터로 본문을 편집할 수도 있으므로 변경 이벤트를 100ms 디바운스 후 WebView로 renderUpdate 메시지 송신.
  • AnchorResolver 좌표계: WebView는 DOM 노드의 data-line 속성(markdown-it 토큰별로 주입)으로 line을 식별. col은 노드 내 텍스트 offset. length는 selection range 길이. AnchorResolver는 이 4-tuple을 {line, col, length}로 정규화.
  • BOM/CRLF 정규화: VSCode TextDocument는 eol 설정을 가지며, line/col은 VSCode가 정규화한 값을 사용. AnchorResolver는 raw 문자열을 다루지 않고 TextDocument.positionAt/offsetAt을 우선 사용 (정규화 책임 VSCode에 위임).

Day 2 — WebView UI (markdown-it 렌더 + 인라인 오버레이 + 코멘트 패널)

예상 소요 1.0 작업일 · 산출물 5개 · 단위 테스트 1종 그룹 (CSP/payload guard)

목표

WebView 내부 vanilla TS 코드를 작성한다. Extension Host가 전달한 markdown-it HTML을 본문 div에 렌더하고, 사용자 selection을 캡처하여 인라인 오버레이(컨텍스트 버튼)를 띄우고, suggestion/question 추가 시 사이드 panel에 항목을 추가한다. 패널 항목 클릭 시 본문 anchor에 스크롤 + 하이라이트 한다. [제출] 버튼은 submit 메시지를 host로 발화하고 placeholder toast가 응답한다.

산출물

  • media/webview/index.html — 단일 HTML 셸. <main id="doc-body"> + <aside id="panel"> + <div id="overlay-root">. CSP meta 태그 (nonce 주입은 host가 처리).
  • media/webview/main.ts — entry point. acquireVsCodeApi() + 메시지 핸들러 + DOM bootstrap.
  • media/webview/inline-overlay.ts — selection 변화 감지(selectionchange) + 떠다니는 컨텍스트 버튼(suggestion/question 추가) DOM 관리.
  • media/webview/comment-panel.ts — 사이드 panel 렌더, 항목 클릭 핸들러(본문 anchor 스크롤 + class 부착), [제출] 버튼.
  • media/webview/style.css — minimal CSS. VSCode 테마 변수(--vscode-foreground) 사용하여 light/dark 자동 대응.
  • tsconfig.webview.json — WebView TS 빌드 설정 (target ES2020, lib DOM, outDir media/webview/).
  • test/editor/payload-budget.test.ts — message payload size 가드 (단일 코멘트 추가 시 JSON.stringify(payload).length < 2048 assert).
  • package.json scripts 추가 — compile:webview, watch:webview, compile:all.

OMC 위임

WebView 코드는 DOM 위주이므로 자동 테스트 어려움. designer agent 별도 lane으로 인라인 오버레이 UX 검토 위임 (보조). 본 day 끝에 F5 smoke로 시각 확인.

기술 노트

  • markdown-it data-line: host에서 markdown-it 인스턴스를 만들 때 {html: false, linkify: true}로 안전 모드. renderer.rules.paragraph_open 등에서 data-line 속성을 token의 map[0]으로 주입하여 WebView가 anchor 계산에 사용할 수 있게 한다.
  • Selection 캡처: document.addEventListener('selectionchange', ...)로 selection 변화 감지. selection 끝나는 시점에 컨텍스트 버튼을 캐럿 근처에 띄움. 빈 selection이면 버튼 숨김. selection 위치 변화로 인한 thrashing 방지 위해 50ms 디바운스.
  • Anchor 부착: 사용자가 컨텍스트 버튼을 누르면 WebView가 selection의 (startContainer dataLine, startOffset, length, type)을 host로 송신. host는 AnchorResolver로 정규화 후 CommentStore.add 호출. 새 코멘트 id가 echo로 돌아오면 panel 갱신.
  • Panel 클릭 → highlight: panel 항목 click 시 host가 아니라 WebView 자체에서 처리 (round-trip 절약). data-comment-id attr로 DOM 노드 찾아 scrollIntoView({block: 'center'}) + classList.add('is-highlighted'). 1.5s 후 highlight 자동 제거.
  • VSCode 테마: CSS 변수 --vscode-editor-background, --vscode-foreground, --vscode-focusBorder 사용. suggestion/question 색상은 --vscode-charts-blue, --vscode-charts-orange 변수 활용.
  • [제출] 버튼: panel 하단 고정. 클릭 시 {type: 'submit'} 메시지만 송신. host는 P3 단계에서 vscode.window.showInformationMessage('제출이 P4 phase에서 활성화됩니다 (placeholder)') placeholder 응답. P4가 이 hook을 LLMOrchestrator로 교체.
  • Payload size guard: WebView → host 메시지 직렬화 후 길이를 postMessage 직전 측정. 2KB 초과 시 OutputChannel 경고 + 송신 거부(현재는 본문이 host에 있어 2KB 도달 거의 불가하지만 회귀 방지).

Day 2.5 — 통합 + P2 영속 회귀 + 종료 조건 검증

예상 소요 0.5 작업일 · 통합 wiring + 회귀 테스트 + code-reviewer 위임

목표

Day 1/Day 2 산출물을 CommentStore와 연결한다. 코멘트 추가/삭제/수정이 사이드카 또는 workspaceState backend로 영속되고, WebView를 닫았다 다시 열어도 코멘트가 복원되는지 수동 회귀로 확인한다. code-reviewer agent 별도 lane spawn하여 P3 전체 일괄 검토.

산출물

  • src/editor/MarkdownReviewEditor.ts 갱신 — resolveCustomTextEditor에서 PersistenceBackendFactory로 backend 생성 후 CommentStore 인스턴스 attach. WebView 메시지 핸들러에서 add/update/remove 시 store.save 호출.

기술 노트

  • CommentSession 책임 경계: WebView 메시지 핸들링(parse/echo)은 WebViewBridge가 담당. CommentStore 호출 및 결과 echo는 CommentSession이 담당. 분리 이유는 단위 테스트에서 store만 mock하면 메시지 흐름 검증 가능하기 때문.
  • Pending save dedup: WebView에서 빠르게 여러 코멘트를 추가하면 save 호출이 누적된다. CommentSession은 200ms 디바운스로 save를 묶고, dispose 시 마지막 pending save를 flush.
  • 영속 backend 선택 시점: resolveCustomTextEditor가 호출될 때마다 workspace.getConfiguration('mdReview').get('persistenceBackend') 읽어 backend 결정. settings 변경은 reload 후 반영 (현재 instance는 lock).
  • WebView reload 시 코멘트 복원: WebView 활성화 시 store.load(docUri) 호출 → 코멘트 array → renderUpdate 메시지로 패널 초기화. 이게 영속 round-trip 통합 검증의 핵심 지점.

5.1 src/editor/MarkdownReviewEditor.ts

import * as vscode from 'vscode';
import MarkdownIt from 'markdown-it';
import { WebViewBridge } from './WebViewBridge';
import { CommentSession } from './CommentSession';
import { createPersistenceBackend } from '../store/PersistenceBackendFactory';
import { CommentStore } from '../store/CommentStore';

export class MarkdownReviewEditor implements vscode.CustomTextEditorProvider {
  static readonly viewType = 'mdReview.editor';

  private readonly md: MarkdownIt;

  constructor(private readonly context: vscode.ExtensionContext) {
    // markdown-it은 host 측에서 단일 인스턴스로 reuse.
    // html: false → 인라인 HTML 차단 (XSS 방지).
    // linkify: true → 자동 링크화.
    this.md = new MarkdownIt({ html: false, linkify: true });
    attachDataLineAttrs(this.md);
  }

  async resolveCustomTextEditor(
    document: vscode.TextDocument,
    webviewPanel: vscode.WebviewPanel,
    _token: vscode.CancellationToken,
  ): Promise<void> {
    const bridge = new WebViewBridge(webviewPanel.webview);

    const config = vscode.workspace.getConfiguration('mdReview');
    const backendKind = config.get<string>('persistenceBackend', 'sidecar');
    const backend = createPersistenceBackend(backendKind, {
      memento: this.context.workspaceState,
    });
    const store = new CommentStore(backend);
    const session = new CommentSession(document, store, bridge);

    webviewPanel.webview.options = {
      enableScripts: true,
      localResourceRoots: [
        vscode.Uri.joinPath(this.context.extensionUri, 'media'),
      ],
    };
    webviewPanel.webview.html = this.renderShell(
      webviewPanel.webview,
      document,
    );

    // 디바운스 후 본문 변경을 WebView로 push.
    // 외부 에디터에서 같은 파일을 편집하는 경우에도 일관 표시.
    const changeSub = vscode.workspace.onDidChangeTextDocument(
      debounce((e) => {
        if (e.document.uri.toString() !== document.uri.toString()) return;
        bridge.post({ type: 'renderUpdate', html: this.renderBody(document) });
      }, 100),
    );

    webviewPanel.onDidDispose(async () => {
      changeSub.dispose();
      await session.dispose();
    });

    await session.start(this.renderBody(document));
  }

  private renderShell(webview: vscode.Webview, _document: vscode.TextDocument): string {
    const nonce = randomNonce();
    const scriptUri = webview.asWebviewUri(
      vscode.Uri.joinPath(this.context.extensionUri, 'media', 'webview', 'main.js'),
    );
    const styleUri = webview.asWebviewUri(
      vscode.Uri.joinPath(this.context.extensionUri, 'media', 'webview', 'style.css'),
    );
    // CSP는 § 7 참조. nonce는 매 open마다 갱신.
    return renderHtmlTemplate({ nonce, scriptUri, styleUri, csp: webview.cspSource });
  }

  private renderBody(document: vscode.TextDocument): string {
    return this.md.render(document.getText());
  }
}

5.2 src/editor/WebViewBridge.ts

import * as vscode from 'vscode';
import {
  HostToWebViewMessageSchema,
  WebViewToHostMessageSchema,
  type HostToWebViewMessage,
  type WebViewToHostMessage,
} from './messages';

export type WebViewMessageHandler = (msg: WebViewToHostMessage) => void | Promise<void>;

export class WebViewBridge {
  private static readonly output = vscode.window.createOutputChannel('mdReview');

  constructor(private readonly webview: Pick<vscode.Webview, 'postMessage' | 'onDidReceiveMessage'>) {}

  post(msg: HostToWebViewMessage): Thenable<boolean> {
    // 송신 직전 schema 검증 — 잘못된 host 코드를 빨리 발견.
    HostToWebViewMessageSchema.parse(msg);
    return this.webview.postMessage(msg);
  }

  onMessage(handler: WebViewMessageHandler): vscode.Disposable {
    return this.webview.onDidReceiveMessage(async (raw: unknown) => {
      const result = WebViewToHostMessageSchema.safeParse(raw);
      if (!result.success) {
        // 잘못된 메시지는 silently drop하지 않고 로그 + drop.
        WebViewBridge.output.appendLine(
          `[bridge] dropped invalid message: ${result.error.message}`,
        );
        return;
      }
      await handler(result.data);
    });
  }
}

5.3 src/editor/AnchorResolver.ts

import * as vscode from 'vscode';
import { type CommentAnchor } from '../model/Comment';

export interface DomSelectionInfo {
  // WebView가 보고하는 selection 정보.
  // startLine: data-line attr으로 식별된 markdown-it token의 시작 행 (1-based 또는 0-based — § 5.3 정책).
  startLine: number;
  startColInLine: number;
  length: number;
}

export class AnchorResolver {
  constructor(private readonly document: vscode.TextDocument) {}

  // DOM 좌표 → CommentAnchor (TextDocument 정규화 사용).
  resolveAnchorFromDom(dom: DomSelectionInfo): CommentAnchor {
    const line = this.clampLine(dom.startLine);
    const lineText = this.document.lineAt(line).text;
    const col = Math.min(Math.max(dom.startColInLine, 0), lineText.length);
    const length = Math.max(dom.length, 0);
    return { line, col, length };
  }

  // CommentAnchor → DOM 좌표 (panel 클릭 → 본문 스크롤 시).
  resolveDomFromAnchor(anchor: CommentAnchor): DomSelectionInfo {
    const line = this.clampLine(anchor.line);
    return {
      startLine: line,
      startColInLine: anchor.col,
      length: anchor.length,
    };
  }

  private clampLine(line: number): number {
    const max = this.document.lineCount - 1;
    return Math.min(Math.max(line, 0), max);
  }
}

import { InlineOverlay } from './inline-overlay';
import { CommentPanel } from './comment-panel';

declare function acquireVsCodeApi(): {
  postMessage(msg: unknown): void;
};

const api = acquireVsCodeApi();
const docBody = document.getElementById('doc-body') as HTMLElement;
const panelRoot = document.getElementById('panel') as HTMLElement;
const overlayRoot = document.getElementById('overlay-root') as HTMLElement;

const overlay = new InlineOverlay(overlayRoot, (selection, type) => {
  const payload = { type: 'addComment', selection, kind: type };
  postWithBudgetGuard(payload);
});

const panel = new CommentPanel(panelRoot, {
  onSubmit: () => postWithBudgetGuard({ type: 'submit' }),
  onItemClick: (id) => scrollAnchor(id),
});

window.addEventListener('message', (e: MessageEvent) => {
  const msg = e.data;
  switch (msg.type) {
    case 'renderUpdate': docBody.innerHTML = msg.html; break;
    case 'commentsUpdate': panel.setComments(msg.comments); break;
  }
});

function postWithBudgetGuard(payload: unknown): void {
  const serialized = JSON.stringify(payload);
  if (serialized.length > 2048) {
    console.warn('[mdReview] payload exceeds 2KB; rejecting send');
    return;
  }
  api.postMessage(payload);
}

function scrollAnchor(id: string): void {
  const el = docBody.querySelector(`[data-comment-id="${id}"]`);
  if (!el) return;
  el.scrollIntoView({ block: 'center' });
  el.classList.add('is-highlighted');
  setTimeout(() => el.classList.remove('is-highlighted'), 1500);
}

6. ADR 운영화

마스터 ADRP3에서의 적용
AD-1: 데이터 모델은 client/server interchangeable JSONWebView ↔ Host 메시지 payload는 Comment 모델 그대로 사용. 추가 변환 layer 없음. zod schema도 P2와 같은 정의 reuse.
AD-3: 모든 외부 입력은 zod로 검증WebView → Host 메시지는 WebViewBridge.onMessage에서 zod parse. Host → WebView도 송신 직전 검증 (양단 검증).
AD-5: VSCode API는 의존성 주입으로 추상화WebViewBridge 생성자는 Pick<Webview, 'postMessage' | 'onDidReceiveMessage'> 인터페이스로만 의존 → 단위 테스트에서 fake 객체 주입.
AD-6 (NEW): 본문은 host 단일 권위 사본본문 raw text는 vscode.TextDocument에만 존재. WebView로는 markdown-it 렌더 결과만 송신. R-5(대용량 직렬화) 1차 방어.

7.1 Content Security Policy

<meta http-equiv="Content-Security-Policy" content="
  default-src 'none';
  style-src ${webview.cspSource} 'unsafe-inline';
  script-src 'nonce-${nonce}';
  img-src ${webview.cspSource} https: data:;
  font-src ${webview.cspSource};
">
  • default-src 'none': 모든 리소스는 명시적으로만 허용 (deny-by-default).
  • script-src 'nonce-${nonce}': 스크립트는 매 open마다 새 nonce 일치 시에만 실행. inline script는 nonce 없으면 차단.
  • style-src 'unsafe-inline': VSCode 테마 변수 사용을 위해 inline style 허용 (테마 색상 동적 변경 지원).
  • img-src ... https: data:: 마크다운 안의 이미지(외부 https 또는 base64 data URI) 허용. 단 본문 markdown-it 렌더가 html: false이므로 임의 <img> 주입은 불가, markdown image 문법만.
